# Умный город — заявки ТСЖ в MAX

Чат-бот и мини-приложение для управления заявками по содержанию многоквартирного дома.
Председатель ТСЖ загружает реестр собственников и ведёт специалистов, собственник создаёт
заявку с фотографиями в MAX, а председатель или назначенный специалист обрабатывает её.
Собственник видит статус заявки и получает уведомления об изменениях.

**Приоритетный сценарий MVP:** от обращения собственника до отслеживаемой заявки и результата
её обработки. Авторизация председателя и импорт реестра подготавливают этот сценарий; код
доступа к записи реестра председатель сообщает собственнику лично.

## Исследование проблемы

Команда провела опрос об обращениях по вопросам управления домом 16–22 сентября 2026 года.
В таблице 24 уникальных ответа, из них 16 — от собственников квартир. Получены следующие
ответы на вопросы, которые задавались всем 24 участникам:

| Вопрос анкеты | Результат |
| --- | --- |
| Бывали ли ситуации, когда было непонятно, на каком этапе находится решение проблемы? | «Да» — 17 из 24. |
| Бывали ли ситуации, когда было непонятно, зарегистрировано ли обращение? | «Да» — 11 из 24. |
| Приходилось ли повторно обращаться по одной проблеме, потому что её не решили? | «Да, один-два раза» или «Да, неоднократно» — 17 из 24. |

Эти ответы поддерживают выбор основного сценария: бот подтверждает создание заявки,
а мини-приложение показывает её статус и изменения. В вопросе с несколькими вариантами
11 из 24 отметили отслеживание статуса как полезную функцию бота. При этом 15 из 24
отметили автоматическое составление готового обращения; текущий MVP этого не делает.

Источник — собственная таблица опроса «2026-09-22 Опрос по УК.xlsx». Опрос охватывает
вопросы взаимодействия с УК в целом, а не только работу ТСЖ. Это небольшая выборка,
по которой нельзя оценивать долю всех жителей с такой проблемой. Контакты респондентов
в репозиторий не загружаются. Опрос не измеряет эффект продукта: на пилоте нужно отдельно
проверить время от создания заявки до изменения статуса, долю завершённых заявок
и повторные обращения по одной проблеме.

## Состав и архитектура

| Компонент | Роль |
| --- | --- |
| `src/bot.py`, `src/max_api.py` | Бот в MAX: авторизация ролей, Long Polling, команды, заявки и уведомления. |
| `src/mini_app.py`, `webapp/` | HTTP-сервер и интерфейс мини-приложения: профили, реестр, специалисты, заявки и статусы. |
| `src/hoa_store.py`, `src/auth_store.py`, `src/verification_store.py` | Хранение пространств ТСЖ, собственников, заявок и состояний авторизации. |
| `src/gigachat_api.py`, `src/chairman_protocol.py`, `src/owner_registry.py`, `src/request_classifier.py` | Работа с GigaChat: анализ протокола и реестра, определение специалиста по тексту заявки. |
| PostgreSQL 16 | Постоянное хранилище при запуске через Docker Compose. |
| Caddy | HTTPS и проксирование мини-приложения при серверном запуске. |

Бот получает события через API MAX, обращается к GigaChat для анализа документов и текста,
а результаты сохраняет в PostgreSQL. Мини-приложение открывается из MAX, передаёт подписанные
стартовые данные своему HTTP-серверу и работает с той же базой. На сервере HTTPS-запросы
к мини-приложению проходят через Caddy. Локальный Compose запускает только бота и PostgreSQL.

Для запуска нужны Python 3.11 (в образе Docker), зависимости из `pyproject.toml`, PostgreSQL 16,
токен бота MAX и ключ GigaChat. HTTP-методы `/api/*` обслуживают мини-приложение; отдельной
интеграции с внешней жилищной информационной системой в MVP нет.

## Запуск через Docker

Понадобится Docker Desktop с поддержкой `docker compose`.

1. Создайте `.env` из примера:

   ```powershell
   Copy-Item .env.example .env
   ```

2. Заполните в `.env` как минимум:

   ```text
   MAX_BOT_TOKEN=токен_бота_MAX
   POSTGRES_PASSWORD=длинный_случайный_пароль
   ```

   Для прохождения основного сценария также задайте `GIGACHAT_CREDENTIALS`: без GigaChat
   недоступны проверка протокола, импорт реестра и классификация быстрой заявки.

3. Запустите весь проект одной командой:

   ```powershell
   .\start.ps1
   ```

   Скрипт соберёт и запустит PostgreSQL и бота. Локальный mini app будет доступен по адресу
   `http://localhost:8080`.

   На Linux и macOS эквивалентная команда из корня репозитория:

   ```sh
   docker compose up --build -d
   ```

4. Проверьте состояние и логи:

   ```powershell
   docker compose ps
   docker compose logs -f bot
   ```

   `http://localhost:8080/health` должен вернуть HTTP 200 и `{"status":"ok"}`.
   Прямое открытие локальной страницы показывает интерфейс, но профиль и заявки требуют
   запуска мини-приложения из MAX с действительной подписью. Для полного сценария в MAX
   подключите к боту публичный HTTPS URL мини-приложения.

### Параметры окружения и порты

| Переменная | Назначение |
| --- | --- |
| `MAX_BOT_TOKEN` | Обязательный токен бота с платформы MAX. |
| `POSTGRES_PASSWORD` | Обязательный пароль PostgreSQL для запуска через Docker. |
| `GIGACHAT_CREDENTIALS` | Ключ GigaChat, обязательный для основного сценария. |
| `POSTGRES_DB`, `POSTGRES_USER` | Имя базы и пользователь; по умолчанию `smart_city`. |
| `MINI_APP_PORT` | Локальный порт HTTP-сервера; по умолчанию `8080`. |
| `MINI_APP_DOMAIN` | Публичный домен при серверном запуске через Caddy. |
| `GIGACHAT_SCOPE`, `GIGACHAT_MODEL`, `GIGACHAT_BASE_URL` | Параметры GigaChat; значения по умолчанию указаны в `.env.example`. |
| `GIGACHAT_CA_BUNDLE`, `GIGACHAT_TIMEOUT` | CA-файл и тайм-аут GigaChat; значения по умолчанию указаны в `.env.example`. |
| `DATABASE_URL` | Адрес отдельного PostgreSQL при запуске без Compose; Compose задаёт его автоматически. |
| `PHONE_VERIFICATION_DB` | Путь к SQLite-файлу при запуске без PostgreSQL; по умолчанию `.data/phone_verifications.sqlite3`. |
| `LOG_LEVEL` | Уровень логирования; по умолчанию `INFO`. |

При локальном запуске `8080/tcp` опубликован только на `127.0.0.1`;
`5432/tcp` PostgreSQL доступен внутри сети Compose и не публикуется на хост.
На сервере Caddy публикует `80/tcp`, `443/tcp` и `443/udp`.

Локальный Compose запускает два сервиса:

- `bot` — MAX-бот с Long Polling и HTTP-сервер mini app на порту `8080`;
- `postgres` — PostgreSQL 16 с проверкой готовности перед запуском бота.

Таблицы подтверждённых номеров, состояний авторизации, пространств ТСЖ, профилей председателей,
собственников, реестров и заявок создаются автоматически. Данные PostgreSQL находятся в Docker volume
`postgres_data` и сохраняются при пересборке или обычной остановке контейнеров.

Остановить сервисы:

```powershell
docker compose down
```

Повторно запустить сервисы без удаления данных:

```sh
docker compose up --build -d
```

Посмотреть записи напрямую:

```powershell
docker compose exec postgres psql -U smart_city -d smart_city `
  -c "SELECT user_id, phone, verified_at FROM phone_verifications;"
```

Команда `docker compose down -v` удаляет volume вместе со всеми данными базы.

## Сквозная проверка основного сценария

Для проверки нужны два разных аккаунта MAX: председатель и собственник, чьи номера можно
подтвердить кнопкой MAX. Специалист необязателен: если подходящего специалиста нет, бот
предложит направить заявку председателю. Нужны доступные MAX и GigaChat, а также:

- протокол правления ТСЖ в PDF, DOC или DOCX с названием ТСЖ, адресом, кворумом,
  вопросом об избрании председателя, решением, ФИО избранного председателя и подписью;
- PDF-реестр того же дома до 15 МБ с записью физического лица: номер помещения, ФИО,
  площадь, доля и сведения о праве собственности;
- от одной до трёх фотографий проблемы, каждая до 10 МБ.

Готовые аккаунты MAX и тестовые документы в репозитории не размещены. Для демонстрации
подготовьте отдельные аккаунты и обезличенные документы, а доступ к ним передайте
проверяющему отдельно. В этом сценарии выполняются реальные обращения к MAX и GigaChat.
Результат анализа документа зависит от его содержания и качества; тестовые или
смоделированные данные нужно явно обозначать при демонстрации.

| Шаг | Действие | Ожидаемый результат |
| --- | --- | --- |
| 1 | Председатель отправляет боту `/auth`, выбирает «Я председатель», делится номером кнопкой MAX и загружает протокол. | После проверки протокола бот создаёт пространство ТСЖ и показывает профиль председателя. |
| 2 | Председатель открывает мини-приложение через `/profile`, загружает PDF-реестр, проверяет адрес, список и пропущенные помещения, затем подтверждает импорт. | В реестре появляется собственник и действующий код входа с временем окончания. |
| 3 | Председатель лично сообщает код нужному собственнику. Собственник отправляет `/auth`, выбирает «Я собственник», подтверждает номер кнопкой MAX и вводит `/code КОД`. | Бот привязывает запись реестра к аккаунту MAX; собственник видит своё помещение через `/profile`. |
| 4 | Собственник нажимает «Быстро создать заявку» или отправляет `/request`, пишет описание проблемы отдельным сообщением, присылает 1–3 фотографии и подтверждает отправку. | Бот сообщает номер и адресата заявки; она появляется со статусом «На рассмотрении». |
| 5 | Председатель открывает карточку заявки в мини-приложении, меняет статус и сохраняет изменения. | Новый статус виден собственнику; собственник получает уведомление в MAX. |

Если подходящий специалист зарегистрирован, заявка назначается ему. Если он ещё не вошёл
в MAX, уведомление получает председатель. Если подходящего специалиста в ТСЖ нет,
собственник подтверждает отправку председателю. Для повторной проверки можно создать
новую заявку с теми же аккаунтами; очищать Docker volume не требуется.

## Авторизация председателя

Сценарий полностью проходит в личном чате:

1. Пользователь выбирает роль «Я председатель».
2. Бот запрашивает номер через кнопку `request_contact` и проверяет HMAC-подпись MAX.
3. Бот запрашивает протокол правления ТСЖ в PDF, DOC или DOCX.
4. GigaChat проверяет тип документа, кворум, вопрос об избрании председателя, результаты
   голосования, решение, ФИО и наличие подписи.
5. При успешной проверке создаются пространство ТСЖ и профиль председателя. Хеш документа
   защищает протокол от повторного присвоения другому номеру.
6. При следующем входе подтверждённый номер автоматически получает свой профиль без повторной
   загрузки протокола.

Обычный контакт из телефонной книги подтверждённым не считается.

Затем председатель открывает mini app и загружает PDF-реестр. GigaChat Ultra извлекает записи
небольшими группами помещений. Председатель проверяет адрес, полный список и пропущенные помещения,
затем подтверждает импорт. Для каждого собственника создаётся код. В интерфейсе
показано время его окончания; код меняется каждые два часа. Председатель лично сообщает нужный код
собственнику по его запросу. При повторной загрузке реестра привязки совпавших записей сохраняются,
а отсутствующие собственники теряют доступ. Строки с неясным ФИО (`???`) и организации не получают
код автоматически.

## Вход собственника и заявки

1. Собственник выбирает «Я собственник», подтверждает через кнопку номер MAX и получает код у
   председателя лично.
2. В личном чате отправляет `/code КОД`. Один код привязывает конкретную запись реестра к аккаунту
   MAX. В чужой аккаунт повторно привязать её нельзя. Для нескольких помещений можно ввести ещё код.
3. После входа бот показывает кнопки «Открыть профиль» и «Быстро создать заявку».
   Во втором сценарии собственник отправляет текстовое описание проблемы.
   GigaChat определяет только тип специалиста; исходный текст сохраняется и передаётся без исправлений.
   Затем собственник присылает от 1 до 3 фотографий
   (каждая до 10 МБ) и подтверждает отправку. Бот назначает зарегистрированного
   сантехника или электрика именно его ТСЖ. При отсутствии подходящего
   специалиста он предлагает отправить заявку председателю. Отмена — `/cancel`.
4. В mini app собственник видит свои помещения, заявки и статусы. Председатель
   видит заявки своего ТСЖ, а специалист — назначенные ему заявки. Нажатие на заявку
   открывает отдельную карточку с исходным текстом, данными и фотографиями.
   Фотография раскрывается по нажатию; несколько снимков можно листать и закрыть крестиком.
   Каждая заявка поступает со статусом «На рассмотрении». После осмотра специалист
   выбирает «В процессе выполнения» или «Отклонена», а после выполнения — «Исполнено».
   Специалист и председатель могут менять статус и задавать приоритет:
   авария, срочно, на сегодня или запланировано. При выборе «Авария» председатель
   получает уведомление. Пока назначенный специалист не исполнит аварийную заявку,
   новые часовые слоты для него недоступны; старые кнопки выбора времени тоже проверяются.
   Оба поля расположены под фотографиями;
   изменения применяются после нажатия «Сохранить изменения». Председатель также
   выбирает исполнителя в карточке и может переназначить заявку другому специалисту
   своего ТСЖ или себе. Новый исполнитель получает уведомление в чате MAX, прежний
   специалист узнаёт о снятии с заявки, а собственник — о каждом изменении статуса.
   Если специалист ещё не вошёл в бот, mini app сообщает председателю, что
   уведомление ему не доставлено.
   В выборе исполнителя председатель отображается по ФИО; среди специалистов
   доступны только вошедшие в бот. Имена в этом выборе показаны как фамилия и
   инициалы с указанием специальности.

Код и подтверждённый номер служат для доступа к пространству ТСЖ. Они не являются независимым
доказательством права собственности: председатель должен передать код именно указанному в реестре
человеку. Код действует до ближайшей границы двухчасового интервала.

Начать можно командой `/auth`, проверить состояние — `/status`, открыть mini app — `/profile`.

## Специалисты

Председатель добавляет сантехника или электрика во вкладке «Специалисты»: указывает ФИО и номер
телефона. Специалист открывает чат с ботом, выбирает «Я специалист» и подтверждает этот номер
кнопкой MAX. При совпадении номера ему открывается профиль с пространством соответствующего ТСЖ.
Статус входа виден председателю в списке специалистов. Быстрые заявки из чата
передаются подходящему специалисту; если он ещё не вошёл в MAX, уведомление
получает председатель, а заявка остаётся назначенной специалисту.

## Mini app

Председатель сохраняет ссылку-приглашение на общий чат ТСЖ в профиле до добавления бота.
Бот сверяет ссылку, которую MAX возвращает для добавленного чата, и выходит из других
обнаруженных групп и каналов. Для получения событий группового чата бот должен быть его
администратором. Если ссылка меняется или удаляется, ранее привязанный чат также проверяется
заново. MAX не предоставляет API для перечисления всех чатов бота, поэтому старые неактивные
чаты без новых событий обнаружить автоматически нельзя.

Встроенный сервер отдаёт профиль, реестр и заявки. Запросы API принимают
только подписанный `window.WebApp.initData`, проверяют его HMAC токеном бота и срок жизни в один
час. Данные из `initDataUnsafe` для авторизации не используются.

Для подключения mini app к MAX нужен публичный HTTPS URL:

1. Публичный mini app развёрнут по постоянному адресу `https://213-171-9-160.sslip.io`.
2. На платформе MAX для партнёров откройте настройки бота.
3. В поле mini app вставьте этот HTTPS URL и сохраните кнопку открытия.
4. Отправьте боту `/profile`, чтобы получить новую кнопку.

На сервере Caddy автоматически получает и обновляет TLS-сертификат. Для запуска или обновления
проекта выполните в каталоге приложения:

```sh
./server-start.sh
```

Серверный Compose запускает `bot`, `postgres` и `caddy`. Проверка публичной доступности:

```sh
curl https://213-171-9-160.sslip.io/health
```

Локальная проверка доступности:

```powershell
Invoke-RestMethod http://localhost:8080/health
```

## Данные, интеграции и ограничения

Источник сведений о ТСЖ и собственниках в MVP — загруженные пользователем протокол
и реестр. Интеграции с ГИС ЖКХ или другой официальной жилищной системой нет.
GigaChat анализирует документы и определяет тип специалиста по описанию заявки.
В PostgreSQL сохраняются профили, записи реестра, подтверждённые номера, состояния
авторизации, заявки, фотографии и результаты их обработки. Для воспроизведения
основного сценария нужны токен бота MAX, ключ GigaChat, аккаунты и документы,
описанные выше. Внешние MAX и GigaChat не запускаются внутри Docker.

Известные ограничения MVP:

- Анализ протокола через GigaChat не заменяет независимую проверку полномочий
  председателя.
- Подтверждённый номер и код дают доступ к записи реестра, но сами по себе не
  доказывают право собственности. Председатель должен передать код именно
  указанному в реестре человеку.
- Код собственника действует до ближайшей границы двухчасового интервала.
  После пяти неверных попыток новый ввод возможен в следующем интервале.
- При повторном импорте реестра привязки совпавших записей сохраняются,
  а отсутствующие записи теряют доступ. Неоднозначные записи и организации
  не получают код автоматически.
- MAX не предоставляет API для перечисления всех чатов бота, поэтому старые
  неактивные чаты без новых событий обнаружить автоматически нельзя.
- Защищённые методы `/api/*` требуют подписанных стартовых данных MAX.
  Прямой вызов этих методов без MAX не воспроизводит пользовательский сценарий.

## Локальный запуск без Docker

Если `DATABASE_URL` не задан, бот использует SQLite-файл из `PHONE_VERIFICATION_DB`:

```powershell
python -m pip install .
python -m src.bot
```

Для прямого подключения к отдельному PostgreSQL задайте стандартный URL:

```text
DATABASE_URL=postgresql://user:password@host:5432/database
```

## Проверка

```powershell
python -m unittest discover -s tests -v
```

Автоматические тесты используют подменённые ответы внешних сервисов и не заменяют
сквозную проверку работающего решения в MAX.

API MAX использует цепочку сертификатов Минцифры. Официальный CA-bundle находится в
`certs/russiantrustedca.pem` и подключается только к HTTP-клиенту проекта; системное хранилище
сертификатов не изменяется.

## GigaChat 3 Ultra

REST-клиент находится в `src/gigachat_api.py`. Он получает и кеширует access token, отправляет
текстовые запросы, загружает изображения и документы для анализа, а после ответа удаляет их из
хранилища GigaChat.

Настройки в `.env`:

```text
GIGACHAT_CREDENTIALS=ваш_Authorization_Key
GIGACHAT_SCOPE=GIGACHAT_API_PERS
GIGACHAT_MODEL=GigaChat-3-Ultra
```

Пример отдельного вызова:

```python
from src.bot import load_env
from src.gigachat_api import GigaChatApi

load_env()
client = GigaChatApi.from_env()
answer = client.generate_text("Кратко объясни, что такое ТСЖ")
print(answer)
```

Ключ авторизации и access token не должны попадать в логи.
